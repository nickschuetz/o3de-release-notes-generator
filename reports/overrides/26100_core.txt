# SIG-Core, 26.10.0

o3de#19361
The Component Creation Class Wizard can now target a project or any Gem, choose the build target, infer the namespace, and generate basic, level, system and LyShine components as well as data assets.

o3de#19510
First pass of removing duplicate and unused CryEngine code, including the Linux and Mac Win32 wrapper types and the legacy memory-status helpers.

o3de#19581
AZStd::array and AZStd::span are now std::array and std::span.

o3de#19585
AZStd::move is now std::move, which lets the compiler's own diagnostics see moves and surfaced several real bugs that are fixed alongside.

o3de#19602
AZStd::pair is now std::pair, so standard algorithms, C++20 ranges and third-party libraries that expect the real type work without conversion.

o3de#19614
AZStd allocators are reworked to C++20 conventions. The implicit allocator(const char*) constructor is gone; it silently turned a string literal into an allocator and produced empty containers.

o3de#19631
The project export script's error for engine asset bundling now says "engine" rather than "game".

o3de#19671
AZ::Curve is now a core math type with its own property editor, moved out of the OpenParticleSystem Gem.

o3de#19733
ScriptContext no longer includes an internal Lua header; the alignment macro it needed is part of Lua's public API.

o3de#19746
ProcessWatcher documents that tethering a child process's lifetime binds it to the launching thread, not the parent process, so launching from a short-lived thread kills the child immediately.

o3de#19751
The o3de Python package honours the O3DE_ENGINE_PATH environment variable when resolving the engine root, so packaged installs where the package lives in a virtual environment find the right engine.

o3de#19752
Configuring a project against a read-only, system-installed engine no longer fails: the engine's Python packages install from a source distribution instead of in editable mode.

o3de#19764
AZ::Transform shrinks from 48 to 32 bytes, with translation and uniform scale packed into one SIMD lane.

o3de#19771
EditorComponentAPI get, set and compare property calls work on components that do not derive from EditorComponentBase, such as Input Configuration, instead of reading the wrapper's memory.

o3de#19801
Gamepads work on Linux systems that have only the libevdev runtime package installed; the loader now tries the versioned library name.

o3de#19805
Fixed a crash on quit when a scripted entity was deactivated after the script system had already shut down.

o3de#19809
AZStd compiles with GCC again after a declval issue in the vendored standard library code.

o3de#19818
Gameplay scripts can read and set the absolute system cursor position and cursor state, making cursor-aimed top-down controls possible from script.

o3de#19852
Translation assets build again on Linux: the Qt6 merge had dropped the rpath fix for lrelease, so libQt6Core was not found.

o3de#19853
Console commands can supply a callback that autocompletes their arguments on Tab.

o3de#19856
Fixed crashes in network-related entity initialisation and in child entities left dangling by the 26.05 transform behaviour change.

o3de#19870
Translation assets build on Mac after the same lrelease rpath fix as Linux.

o3de#19882
The ImGui console no longer collects stray text while the ImGui layer is hidden; input is queued and delivered only when it is visible.

o3de#19890
AZStd replaces its SFINAE machinery with C++20 concepts and drops the type traits, atomic aliases and iterator helpers that the standard library now covers.

o3de#19895
Fixed a crash in the Inspector when modifying values, caused by a callback type mismatch in the Document Property Editor that had gone unnoticed for years.

o3de#19905
Engine registration no longer consults the engines_path field deprecated in 22.10, which fixes a silent failure when registering an engine whose name already existed at a different path.

o3de#19929
The Inspector refreshes when a property's ChangeNotify attribute says it should.

o3de#19943
A new GameplayGem template scaffolds C++ gameplay components in a controller architecture, with EBus interfaces, serialisation and Editor reflection, visual scripting reflection, unit test skeletons and platform abstraction files.

o3de#19952
The Groundplane asset folder is spelled correctly, and the 28 prefabs, levels and templates that referenced the misspelled path are updated.

o3de#19963
LuaIDE works with the Editor on Linux: inter-process communication now has a Linux implementation, and two bugs in document invalidation and file lookup are fixed.

o3de#19985
dlmalloc and nedmalloc are removed from AzCore; they are unmaintained upstream and slower than native allocators on modern platforms.

o3de#19993
Fixed a crash when detaching a prefab, and an ImGui crash.

o3de#20027
Lua scripts can construct an InputDeviceId with a name and index, so they can address a specific device such as the second gamepad.

o3de#20052
Fixed a crash in Restore Default Layout when no Console view pane exists.

o3de#20113
SystemFile reads and writes larger than 2 GB are chunked on Linux and Mac instead of failing or truncating.

o3de-extras#1064
The ROS 2 project template no longer enables unused automoc and autorcc.

o3de-extras#1087
Fixed a wrong AZ::IO::Path construction in the Robot Importer's asset lookup that could produce a bad lookup key.
